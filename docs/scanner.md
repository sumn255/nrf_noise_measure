# 全频段扫描、峰值保持和按钮光标

SI24 已由用户实机确认：寄存器自检通过、接收模式初始化成功，而且在 2412 MHz 出现检测命中。这证明基础 SPI 通信和检测链路能够工作，不代表已经测得绝对射频功率。

现在固件会连续扫描 **2400～2525 MHz，共 126 个频点（通道 0～125），步进 1 MHz**，显示绿色实时柱、黄色峰值标记及白色光标，替换先前的彩条测试画面。

## 按钮接线

使用一颗常开瞬时按钮，连接如下：

```text
Longan Nano PB8 / B8 ──── 按钮 ──── GND
```

内部上拉已经在 `app.overlay` 启用，松开为高电平，按下接地为有效。普通短接线测试不需要额外上拉电阻。请不要把按键接到 5 V。

若使用四脚轻触按钮，需先确认两组内部相连的引脚，PB8 和 GND 分别接在按下才会导通的两侧；不要把两条线接到内部本来就短接的一组脚上。

- 每次按下并稳定 30 ms，光标向右移动 1 MHz。
- 初始选择 **2412 MHz**，最后一个是 **2525 MHz**，再按回到 **2400 MHz**。
- 按下被消抖确认后，持续按住 500 ms 开始连移，此后每 100 ms 右移一格；松开即停止。主循环阻塞时不会补发一串积压事件。
- 上电时一直按住不会产生一次误触发，先松开再按即可。

其他接线保持不变：

| 功能 | Longan Nano |
|---|---|
| SI24 CE | PB10 |
| SI24 CSN | PB12 |
| SI24 SCK / MISO / MOSI | PB13 / PB14 / PB15 |
| 日志 TX / RX | PB6 / PB7 |
| 新按钮 | PB8 → 按钮 → GND |

SI24 仍由 3V3 供电、共地，仍需拔掉 microSD 卡。

## 屏幕怎么看

屏幕示意，具体柱高随测量变化：

```text
2412MHZ 25% P50%             ■
   LIVE  PEAK    ACT %
100 ┤       ─          ─       ← 黄色峰值标记
    │       │    ─     │
 50 ┤   │   │    │     │
    │ │ │   │  │ │  │  │       ← 绿色实时柱
  0 └──────────────────────
        ▲                       ← 白色光标箭头
    2400      2460      2525
```

顶行显示选中频点、最近窗口检测命中率，以及该频点的峰值保持读数 `P`。绿色柱采用平滑动画，因此柱高与顶行未平滑的命中率可能短暂有差异。

横轴为频点中心频率，纵轴是 **检测活动度 0～100%**。例如 `25%` 表示该频点最近 16 个独立接收窗口中有 4 个命中。它是一个用于比较强信号活动的相对指标，不是射频幅值、RSSI、dBm 或精确 Wi-Fi 占用率；0% 也不代表没有弱信号。

每个频点在图中占 1～2 像素，126 个频点按频率顺序映射到绘图区。白色虚线及底部箭头标出所选频点；用按钮逐点查看顶部频率，避免依靠肉眼数像素。扫描通道增加后，同样的采样窗口需要更长时间集齐，预热和活动度响应会相应变慢。

峰值标记捕获检测活动度及平滑柱高的较大值。达到或追平新峰值时重新保持约 **1 秒**，之后以约 **25 个百分点/秒**向下衰减，且不会落到实时柱下方。它是音响指示器风格的短时峰值保持，不是从开机起永久保持最大值。

其他提示：

| 提示 | 含义 |
|---|---|
| `WARMUP`，顶行 `--%` | 尚未集齐每频点 16 个有效样本，先不绘制有误导性的峰值 |
| `ACT %` | 正常绘制检测活动度 |
| 右上绿色方块 | SI24 初始化和最近检查没有报告错误 |
| `SI24 ERR -数字`，右上红块 | 驱动错误，图形冻结，不把失败当成“无干扰” |
| `KEY ERR` | 按钮 GPIO 失败，扫描仍继续 |

启动预热时间取决于实际扫描、屏幕写入和日志耗时，请等待一会儿。LED 保留约 1 秒的完整亮灭周期，屏幕不再使用彩条和原来的心跳方块。

## 扫描和显示如何同时工作

应用仍是一个主线程，不需要同时操作驱动的多个线程：

```text
读按钮并消抖 → 采 4 个频点 → 更新动画（到期时）
       ↑                         ↓
       └── 休眠 1 ms ← 写 4 行 LCD
```

每个频点执行一次独立 CE 窗口，然后移到下一个频点；扫完一轮再回来采下一次。每轮起点向右轮换一个频点，减轻与周期性信号反复对齐的偏差，但并不能消除所有采样偏差。

各频点用 16 位历史保存最近 16 次检测结果，滑入新结果时移出最旧结果。这叫**滚动窗口**：响应时间随实际扫描速度变化，不必攒完多轮后一次性更新整个数组。

画面计划每约 100 ms 开始一帧；实际刷新率以串口的 `fps` 为准。显示一次只写连续 4 行，使用 **1280 字节**像素缓冲。主循环在两块之间继续采样和读按钮，所以不用在整屏 SPI 传输期间一直等按钮。每一帧先保存显示快照，确保本帧的频率文字、光标和柱形来自一致的数据；中途按键在后续帧生效。

## 平滑和峰值的关键概念

SI24 检测值只有 0 或 1，直接每次显示它只会得到全高/全低闪烁。这里先统计窗口命中率，再对显示高度做有限速率的上升、下降：上升最快约 400 个百分点/秒，下降最快约 120 个百分点/秒。

动画使用整数定点数：1% 表示为 256，100% 为 25,600。这样在没有硬件浮点单元的 MCU 上也能细分动画，不需要每次用浮点数计算。

峰值有独立的保持期限和下降速度；它不会因为实时柱下降而立刻消失。模型根据经过的毫秒数更新，尽量避免实际帧率变化导致动画速度明显改变。

## 按钮消抖的关键概念

机械触点按下或松开时会快速抖动，直接用电平跳变计数可能按一次移动多次。`button_filter.c` 维护候选状态、稳定状态和候选持续时间，只有连续稳定 30 ms 才接受变化。

识别稳定的按下沿时先产生一个事件，然后设定 500 ms 的长按期限；到期后每 100 ms 产生一次重复事件。第一次读到松开就暂停连移，稳定松开后重新允许下一次按下事件。GPIO 的 `GPIO_ACTIVE_LOW` 让 `gpio_pin_get_dt()` 直接返回逻辑上的“按下”，不需要应用再手工反相一次。轮询与屏幕分块写入相结合，本次不需要 GPIO 中断或工作队列。

长按参数在 `src/button_filter.h` 的 `BUTTON_REPEAT_DELAY_MS` 和 `BUTTON_REPEAT_INTERVAL_MS` 中调整。时间从稳定按下被确认时起计算，实际重复间隔还受主循环轮询耗时影响。

## 编译与验收

```powershell
cd E:\dev\nrf_noise_measure
.\scripts\build.ps1 -Pristine
# 进入 DFU 后：
.\scripts\flash.ps1
# 释放 BOOT0、复位；COM5 改为实际串口：
.\scripts\monitor.ps1 -Port COM5
```

上板后建议这样验证：

1. 等 `WARMUP` 消失，确认有绿色柱或空闲零线、黄色峰值及白色光标。
2. 按一下 PB8 按钮，确认从 2412 变为 2413 MHz；持续按住约半秒后连续右移，松开停止，到 2525 MHz 后回到 2400 MHz。
3. 改变附近 Wi-Fi 流量，观察相关频段的检测柱变化。Wi-Fi 信号有带宽，不会只占一个 1 MHz 频点；弱信号可能仍不触发检测。
4. 流量减少后，观察绿色柱先回落，黄色峰值保持后缓慢下降。
5. 看串口的 `sweeps/s`、`fps`、`err`、`KEY`，确认未发生驱动错误；不要在微秒采样窗口内部逐次打印日志。

每秒日志示例：

```text
2412MHz hits=4/16 valid=1 activity=25% peak=50% sweeps/s=... fps=... err=0 LCD=ok KEY=ok
```

日志颜色转义已关闭，普通串口工具不会再显示多余的 ANSI 颜色控制字符。

## 文件和可调参数

| 文件 | 职责 |
|---|---|
| `src/main.c` | 扫描调度、输入读取、日志和 LED |
| `src/si24r1.c` | SI24 寄存器与独立接收窗口 |
| `src/spectrum.c` / `.h` | 滚动统计、平滑动画、峰值和光标 |
| `src/spectrum_display.c` | 分块绘制、文字和频率坐标 |
| `src/button_filter.c` | 纯逻辑消抖，无硬件依赖 |
| `app.overlay` | 按钮 PB8 上拉、SI24 和串口接线 |

`SPECTRUM_PEAK_HOLD_MS` 控制峰值保持时间；`spectrum_animate()` 内的三个速率控制动画。`FRAME_INTERVAL_MS` 控制目标显示周期，`SCAN_BATCH` 控制每次写 LCD 前扫描的频点数。

当前历史结构固定为 **16 位、16 个样本**，不是仅改一个宏就能支持任意样本数；若改变窗口长度，需要同时调整历史类型、最旧位索引和测试。
