# SI24R1 驱动与接线

这一阶段增加的是**扫描器所需的接收检测驱动**，包含 SPI 通信、寄存器读写自检、接收模式初始化、单窗口能量检测和掉电接口。没有实现数据包收发、自动应答或无线发射。

本文保留驱动初次验证阶段的单频测试说明。用户已确认初始化和单频检测通过；当前应用已升级为 **2400～2525 MHz 全频段扫描**，画面和 PB8 按钮说明见 [扫描器教程](scanner.md)。下文的彩条、左下状态块和 20 次单频日志属于历史验证画面，不再是当前默认 UI。

## 接线

先断电接线，并**拔掉 microSD 卡**。SI24 使用 SPI1，而 SPI1 和 PB12 片选也连接板载 SD 卡槽。禁用 SD 驱动不能消除物理上的片选冲突。

| SI24R1 模块丝印 | Longan Nano 引脚 | 作用 |
|---|---|---|
| VCC / 3V3 | 3V3 | 3.3 V 供电 |
| GND | GND | 公共地 |
| SCK / CLK | PB13 / B13 | SPI1 时钟 |
| MISO | PB14 / B14 | 模块输出，主控输入 |
| MOSI | PB15 / B15 | 主控输出，模块输入 |
| CSN / CS | PB12 / B12 | SPI 片选，低有效 |
| CE | PB10 / B10 | 接收使能，高有效 |
| IRQ | 不接 | 当前采用轮询，不需要中断线 |

按模块和板子的**信号丝印**接线，不根据网上图片猜 2×4 排针方向；不同模块的排针排列可能不同。模块 VCC 使用 3.3 V，不能接开发板 5 V。普通模块可先从开发板 3V3 供电，模块端 VCC-GND 并联 100 nF 和约 10 µF 电容，信号线尽量短。带额外 PA/LNA 的模块供电需求应按其模块资料确认，不能按裸 SI24R1 的电流推断。

LCD 仍使用 SPI0；调试 USART0 已重映射到 PB6/PB7，不与 SI24 接线冲突。LED、USB DFU 和 JTAG 的引脚也不用于 SI24 接线。

参考：[Sipeed 板卡资料](https://wiki.sipeed.com/hardware/en/longan/Nano/Longan_nano.html)、项目内固定版本的 `longan_nano-common.dtsi` 和 `longan_nano-pinctrl.dtsi`；[SI24R1 芯片数据手册入口](https://www.lcsc.com/datasheet/C14436.pdf)。

## 编译与运行

```powershell
cd E:\dev\nrf_noise_measure
.\scripts\build.ps1 -Pristine

# 开发板进入 DFU 后执行。
.\scripts\flash.ps1

# 换成 USB 转串口模块对应的端口，打开以后复位开发板。
.\scripts\monitor.ps1 -Port COM5
```

首次添加 overlay 或 binding 后建议 pristine 构建。你在本机安装的 Zephyr SDK 是默认构建工具链；没有修改 `build.ps1` 的工具链选择。

预期启动日志包括：

```text
Probe STATUS=0x0e (not a chip ID)
Register self-test passed; RX only, ACK off, SPI 1000000 Hz
SI24 CONFIG=0x7f EN_AA=0x00 EN_RXADDR=0x00 RF_SETUP=0x08 CH=12
SI24 2412 MHz: detector hits=0/20 (not dBm)
alive: uptime=... ms, LED=ok, LCD=ok, SI24=ok
```

STATUS 可能因之前运行状态而变化，不能只靠它的值识别芯片。初始化还会往 RF_CH 写入两个不同值并读回，以及核对其他配置寄存器。

LCD 保留彩条和右下角心跳，新增**左下角小方块**：

- 红色：SI24 初始化或后续检测失败，查看串口错误码。
- 绿色：自检通过，最近一批窗口没有检测命中。
- 黄色：最近一批窗口至少命中一次。

所有窗口为零不一定是接线错误：这里只测一个频点，而且每秒只观察很短的一段时间。附近信号可能较弱、在其他频点或恰好不在采样时间内。自检通过说明 SPI 寄存器通信基本正常，但不等于射频前端已经经过校准或验证。

接线改变后需要断电操作，再启动程序；当前失败后不自动重新初始化。初始化失败时 LED、屏幕和日志继续工作。

## 驱动组织

| 文件 | 作用 |
|---|---|
| `app.overlay` | 启用 SPI1 的 SI24 节点，指定片选、CE、时钟；禁用 SD 节点 |
| `dts/bindings/radio/zephyr,si24r1-scanner.yaml` | 本应用自定义的设备树 binding，声明必须提供 CE GPIO |
| `src/si24r1.h` | 公开驱动接口与设备上下文 |
| `src/si24r1.c` | SPI 协议、寄存器自检、接收窗口与状态读取 |
| `src/main.c` | 使用驱动并显示/打印结果 |

这是应用内的同步驱动模块，使用 Zephyr 的 SPI/GPIO API；不是已经注册到上游网络子系统的 Zephyr radio device。当前由主线程独占，不能从 ISR 调用；未来若扫描和 UI 分线程，需要先为所有驱动操作加串行访问保护。

接口：

```c
int si24r1_init(struct si24r1 *radio);
int si24r1_sample(struct si24r1 *radio, uint8_t channel,
                 uint32_t window_us, bool *detected);
int si24r1_get_snapshot(struct si24r1 *radio,
                       struct si24r1_snapshot *snapshot);
int si24r1_power_down(struct si24r1 *radio);
```

返回 0 表示成功，负数为 Zephyr 错误码。`sample()` 仅在成功时更新输出参数，失败时不会把错误当成“信道安静”；窗口有效范围为 200～5000 µs，频点编号为 0～125。掉电后需要重新 init 才能采样。

## 这次新增的概念

**SPI 和 GPIO DT spec。** `SPI_DT_SPEC_GET()` 从设备树生成总线、目标频率和片选配置。`reg = <0>` 是 `cs-gpios` 中片选的索引，不是 I²C 地址，也不是 RF_CH 编号。`GPIO_DT_SPEC_GET(..., ce_gpios)` 单独描述 CE。

**CSN 与 CE。** CSN 控制一笔 SPI 命令的开始和结束，CE 控制无线接收窗口，不能将两者短接。驱动用一次 `spi_transceive_dt()` 完成“命令字节 + 数据字节”，保证两个字节间 CSN 不被抬高。SPI 使用 mode 0、8 位、MSB first，请求时钟 1 MHz，先以较低速率验证接线。

**配置写入与读回。** SPI 控制器传输成功，不代表模块真的回应了。驱动会检查 RF_CH 的两个测试值和 RX 初始化寄存器，能发现断线、MISO 固定高/低等常见问题。这不是唯一芯片 ID 检测，兼容的 nRF24 类芯片也可能通过。

**被动检测。** 初始化将 EN_AA 和 EN_RXADDR 清零，不使用地址匹配、数据包接收 FIFO 或自动 ACK。CONFIG 选择接收模式，不发送有效负载；IRQ 不接，状态通过 SPI 轮询。

**独立接收窗口。** 每个样本都执行 CE 低 → 设置频点并读回 → CE 高 → 等待 200 µs → CE 低 → 读取 0x09 的 bit 0。等待包含接收稳定时间；不会在同一锁存窗口连续读 20 次并把它当成 20 个独立样本。窗口间 CE 保持低电平并留出间隔。

**检测值不是功率。** 输出只有一个检测位。不要将 SI24 的检测阈值和不同兼容芯片的阈值当成已经验证一致，也不要把 `hits/20` 换算成 dBm。现在 20 个窗口集中在一小段时间内，主要用于驱动验证，不是长时间信道占用率估计。

## 排查顺序

1. `STATUS=0xff` 或初始化读回错误：先检查 VCC/GND、CSN、MISO/MOSI 是否接反、模块排针方向，以及是否拔掉 SD 卡。
2. 自检通过但一直零：先核对当前测试频点是 2412 MHz，不是全频段扫描；用附近信道 1 的 Wi-Fi 流量做对照，再尝试其他测试频点。
3. 运行一段时间后报采样错误：检查电源去耦、接线长度和接触；驱动会停止后续采样并显示红块。
4. 如果模块资料不叫 SI24R1，或者存在额外使能引脚，先按实际模块资料确认，再调整驱动与接线。
